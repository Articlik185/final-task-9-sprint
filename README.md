**Поиск максимума: последовательный и конкурентный Go**

Учебный проект сравнивает поиск максимального элемента слайса последовательно и с разделением работы между восемью горутинами.

**Где смотреть решение**

[Ветка first-iteration](https://github.com/Articlik185/final-task-9-sprint/tree/first-iteration) содержит реализацию и тесты. [Учебный PR №1](https://github.com/Articlik185/final-task-9-sprint/pull/1) открыт. В main сохранён незавершённый исходный шаблон.

**Что реализовано**

- Генерация положительных псевдослучайных чисел.
- Последовательный поиск максимума.
- Разбиение слайса на восемь частей и синхронизация через sync.WaitGroup.
- Проверки пустого слайса, отрицательных чисел, повторяющихся максимумов и неравномерного разбиения.

**Проверка**

Требуется Go 1.24.1 или новее:

    git switch first-iteration
    go test -v ./...
    go test -race ./...

**Демонстрация**

    go run .

В программе SIZE равен 100 000 000: на 64-битной системе только слайс int занимает около 800 МБ. Для небольшого компьютера уменьшите SIZE перед запуском. Время измеряется в микросекундах. Это демонстрация, а не строгий бенчмарк; восемь горутин не гарантируют восьмикратное ускорение.
